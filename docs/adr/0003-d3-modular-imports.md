# ADR-0003 · D3 按子包引入，且只经一个入口

**状态**：已采纳 · 2026-09-16

## 决策

全站禁止 `import * as d3 from 'd3'`。所有 D3 导入必须经过 `src/lib/d3-kit.ts`，由它从 `d3-scale` / `d3-selection` / `d3-shape` 等子包再导出。

## 理由

- 整包 d3 约 270 KB（gzip 前更大），而每个演示实际只用到两三个子模块。
- 单一入口让「全站到底用了 D3 的哪些能力」成为一个可以一眼看完的清单，也让替换/裁剪有唯一的改动点。
- 实测：全部子模块的并集打包后 36 KB，且是**共享块** —— 打开第二个演示时不重复下载。

## 代价

新增演示若需要用到未导出的子模块，要先在 `d3-kit.ts` 里加一行。这是刻意的摩擦：它强迫作者意识到自己正在扩大依赖面。

冷门且体积大的子模块（`d3-contour`、`d3-hierarchy`）不放进 `d3-kit`，由使用它的演示单独动态 `import()`，避免污染共享块。

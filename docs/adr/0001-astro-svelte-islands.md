# ADR-0001 · 用 Astro + Svelte 孤岛，而不是 SPA

**状态**：已采纳 · 2026-09-16

## 背景

这是一个内容站：六章教学正文 + 32 个交互演示。读者的主要行为是阅读，交互是点缀。

## 决策

用 Astro 做静态站点生成，Svelte 只用于交互孤岛。

## 理由

- **内容站的首屏成本应该接近零**。SPA 方案下，读者要下载整个应用框架才能看到第一段文字；孤岛方案下，章节页的首屏 JS 只有 1.7 KB（三 Tab 控制器）。
- **演示天然适合孤岛模型**。32 个演示彼此独立、互不通信，正是「岛」的定义。它们通过 `registry.ts` 的动态 `import()` 按需加载 —— 读者不打开某个演示，就永远不会下载它的代码。
- **SEO 与可分享性**。每个小节都有稳定的 URL（`#s-4-2--demo`），静态 HTML 可被完整索引。

## 代价

- 跨孤岛通信只能走 DOM 事件（本站用 `lc:themechange` 通知所有 D3 图表重新取色）。这在本项目里是够用的，但如果未来需要复杂的跨岛状态，会需要引入共享 store。
- Astro 的 Svelte 集成会把具名插槽内容**再序列化一份**给岛屿。本站因此避免了「把长正文作为 slot 传进岛屿」的写法（见 `SectionTabs.svelte` 的架构说明）—— 五个小节的讲解面板若走 slot，会多出约 70 KB 的重复字节。

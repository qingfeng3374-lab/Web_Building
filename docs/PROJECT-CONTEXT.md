# 《页面布局之道》项目上下文（供 GPT 使用）

> 用途：本文件是为后续让 GPT 撰写“项目亮点”、答辩材料、作品介绍、README 优化、演讲稿或复盘而整理的**当前实现上下文**。除非另有说明，请以本文件和源码为准，不要把旧设计文档中的方案当成已经实现的功能。

## 1. 项目一句话定义

《页面布局之道》（The Craft of Page Layout）是一个**纯前端、双语、交互式的网页布局教学网站**。它不把 CSS 当作零散属性来讲，而是围绕一个 NeoCampus 新生数据看板，用“内容层 → 间距层 → 尺度层 → 结构层 → 视觉层 → 适应层”的依赖顺序，展示同一份语义化 DOM 和同一份数据如何只通过逐层增加 CSS 能力，从原始数据文档生长为可交付界面。

项目的核心立场是：**布局不是把元素摆得好看，而是把注意力调度到正确的地方；每个布局决策都应有可解释的理由和可验证的结果。**

## 3. 目标用户与学习体验

### 目标用户

- 正在学习 CSS 布局、响应式设计和信息层级的前端初学者。
- 想从“会写属性”进一步理解“什么时候该用什么布局规则”的开发者或设计学习者。
- 希望通过可操作实验而非静态截图理解布局原理的学习者。

### 学习闭环

每个小节严格提供三种视图：

1. **讲解（Explain）**：理论来源、为什么有效、何时可能失效，并落到当前案例。
2. **关键代码（Key Code）**：代码要解决的问题、关键点和常见陷阱。
3. **演示（Demo）**：真实计算、可交互的实验；用户拖动滑块、改变参数或切换模式后，图表与指标实时重算。

因此项目不是“文章 + 几张配图”，而是“理论—代码—操作验证”的闭环。所有小节都有理论引用、代码和演示；缺任一项会在构建期被拦截。

### 首页

首页不是简单的链接列表，而是用四段内容建立课程心智模型：

- 深色 Hero：说明课程主张，提供“从第一章开始”和“案例馆”入口。
- 六层互动展台：将六层能力按依赖关系呈现，展示每层增加了什么、包含多少小节、推动了什么指标。
- 章节卡片：展示六章主题、摘要、核心产出与指标变化。
- 贯穿案例：强调“同一份 DOM、同一份数据，只有 CSS 在生长”。
- 使用方式：明确三面板的学习方法，并提示 `G` / `B` 布局审查工具。

首页背景的 p5 生成式版面遵循课程本身的约束：12 列网格、允许的跨列宽度、1.25 排版音阶、8pt 间距标尺和“每屏只有一个主块”的层级约束。

### 章节页

每章包含：

- 顶部章节栏和当前章高亮。
- 带 p5 丝带装饰的章节页头。
- 可跟随滚动的章节目录。
- 位于章首的“贯穿案例”窄入口；点击后通过原生 `<dialog>` 打开案例面板。
- 每个小节的“讲解 / 关键代码 / 演示”Tab。
- 上一章、课程门户、案例馆、下一章之间的导航闭环。

案例弹窗不常驻占据页面空间。它提供当前阶段的真实看板、本章将增加的能力、章节路线、具体改动、该层负责的指标，并可切换预览下一阶段。这种设计让案例上下文随时可查，同时不打断重复阅读。

### 案例馆

案例馆把课程内容沉淀为可复用工具，包含：

- **建造时间轴**：点击任意阶段，切换到该阶段的真实 Dashboard DOM，并查看改动和指标。
- **阶段对比**：默认对比 stage0 与 stage6，可用可拖动分割线比较两个阶段；也可以切换并排模式、网格覆盖和基线覆盖。
- **六层—指标表**：展示每层增加的能力、负责推动的指标、进入和离开该层时的数值，以及对应案例小节。
- **布局决策树**：将“该用 Flow、Flex、Grid、容器查询还是其他模式”的判断指回具体课程小节。
- **布局自检清单**：用于上线前检查，其中可自动检测的条目强调应进入 CI，而不是依靠人工记忆。

## 5. 课程主线：布局的六层

六章不是六个松散主题，而是一条有依赖关系的建造顺序：

```text
内容层 → 间距层 → 尺度层 → 结构层 → 视觉层 → 适应层
```

依赖逻辑为：没有内容与行长，就无法讨论有意义的间距；没有分组，就难以收敛出尺度；没有尺度，结构难以统一；没有结构，视觉层级会被迫用装饰补偿；前五层没有做好，响应式只能依赖越来越多的媒体查询打补丁。

### 第 1 章：内容层——不写 CSS 就已经有的布局

核心观点：浏览器的常规流是默认且稳健的布局起点，先学习不要破坏它。

- 常规流：理解默认布局为什么在窄屏和宽屏都可读。
- 内容决定尺寸：使用内在尺寸，避免通过固定宽高或裁剪掩盖内容问题。
- 行长：将正文约束到舒适阅读区间，强调在定位元素前先决定一行有多长。
- 案例：`stage0 → stage1`，把原始数据变成可读文档。

对应演示：FlowLab、SizingLab、DensityLab、CaseS1。

### 第 2 章：间距层——用空白说话

核心观点：间距是最低成本的分组手段，边框是更昂贵的补充手段。

- 人眼自动分组：以格式塔的接近、相似、共同区域等原则解释分组。
- 间距标尺：将连续、随意的间距选择收敛为有限、可沟通的选项。
- 垂直节奏：让纵向间距落在可解释的隐形基线上。
- 案例：`stage1 → stage2`，仅用空间和面色建立分组，不依赖大量边框。

对应演示：GestaltLab、SpacingScaleLab、RhythmLab、CaseS2。

### 第 3 章：尺度层——让每个数值都有理由

核心观点：好的布局不是“摆得好看”，而是每个尺寸和位置都可追溯。

- 从瑞士网格到 Web 网格：12 列网格的意义及 Web 连续视口与印刷媒介的差异。
- 列宽数学：计算列宽和内容所需跨列数，而不是凭感觉决定卡片宽度。
- 排版音阶：字号不是逐个挑选，而是由比例系统生成。
- 案例：`stage2 → stage3`，用网格、间距标尺和排版音阶替代试出来的数值。

对应演示：GridBuilder、ColumnMath、TypeScaleLab、CaseS3。

### 第 4 章：结构层——把布局写成可评审的文本

核心观点：Flow、Flex、Grid 不是三种随意替换的写法，而是不同的布局模型；DOM 顺序也是结构的一部分。

- Flex 与 Grid 的分工：一维内容流与二维对齐需求的选择。
- `grid-template-areas`：把页面结构写成可阅读、可评审的“字符画”。
- Box Alignment：统一理解 `justify`、`align`、`content`、`items`、`self` 对剩余空间的分配。
- DOM 顺序：不通过 `order` 制造视觉顺序与键盘焦点顺序的冲突。
- 案例：`stage3 → stage4`，建立可读的看板骨架。

对应演示：FlexVsGrid、AreaPainter、AlignmentMatrix、TabOrderLab、CaseS4。

### 第 5 章：视觉层——让最重要的东西看起来最重要

核心观点：结构决定内容在哪里，视觉层级决定用户先看到什么。

- 扫视路径：解释 F 型、Z 型、古腾堡图等模型的适用边界。
- 视觉层级：通过尺寸、字重、对比度、位置、留白等杠杆，将“好看”转成可讨论的层级分。
- 平衡与光学居中：区分数学居中和视觉上看起来居中。
- 深度与层次：阴影只是层次表达方式之一，暗色主题下更依赖亮度分层。
- 节奏、重复与装饰克制：避免均匀造成单调、随机造成噪声，也避免没有信息目的的边框和阴影。
- 案例：`stage4 → stage5`，让核心指标在视觉上真正成为主角。

对应演示：ScanPathLab、HierarchyLab、BalanceLab、ElevationLadder、RhythmComposer、ChromeRatio、CaseS5。

### 第 6 章：适应层——在所有尺寸上都保持对

核心观点：响应式不是为不同设备各写一套页面，而是让同一套规则在不同空间条件下持续成立。

- 内容断点：断点来自内容开始拥挤的临界点，而不是“768、1024”等设备名称。
- `clamp()` 数学：用两个锚点推导流体字号的斜率，而不是随意试 `vw`。
- 容器查询：组件根据自己的容器宽度而不是整个视口宽度适应。
- 算法布局：使用 `minmax`、`auto-fit` 等机制减少对断点的依赖。
- 重排、缩放与目标尺寸：面向 400% 缩放和低视力用户检查可用性。
- CLS：预留媒体尺寸、避免加载时页面跳动。
- 布局性能：识别读写交替引发的 layout thrashing，并使用包含机制降低代价。
- 案例：`stage5 → stage6`，让页面在 320px 至 2560px、键盘操作和加载过程里都保持稳定。

对应演示：BreakpointFinder、ClampPlotter、ContainerQueryLab、IntrinsicPatterns、ReflowAudit、CLSLab、ThrashLab、CaseS6。

## 6. 贯穿案例：NeoCampus 新生数据看板

### 案例设计

看板包含标题、筛选器、摘要、8 个 KPI、趋势图、学院分布、表格和操作按钮。所有阶段使用相同内容和相同 DOM 顺序；业务重要度也从起点就已写入 DOM，避免后续靠 CSS `order` 重排。

`Dashboard.svelte` 通过 `stage0` 到 `stage6` 的数据属性控制 CSS 层层增加。它的叙事不是“修复一个错误页面”，而是从“还没有布局”开始建造：stage0 已有语义正确的 HTML 和浏览器常规流，只是尚未附加布局规则。

### 七个阶段及可观察变化

| 阶段 | 名称 | 增加的能力 | 代表性结果 |
| --- | --- | --- | --- |
| stage0 | 原材料 | 内容 + 浏览器默认样式 | 原始数据文档，行长约 138ch，CLS 0.31 |
| stage1 | 内容层 | 行长约束、行距、内在尺寸、常规流 | 正文行长进入舒适区，约 66ch |
| stage2 | 间距层 | 三级间距、共同区域、垂直节奏 | 分组比从 1.0 提升到 2.0 |
| stage3 | 尺度层 | 12 列网格、8pt 间距标尺、1.25 排版音阶 | 每个位置和尺寸有可追溯的尺度依据 |
| stage4 | 结构层 | `grid-template-areas`、Flex/Grid 分工、对齐、正确 DOM 顺序 | 结构可作为文本评审，可访问性问题减少 |
| stage5 | 视觉层 | 三级层级、视觉平衡、面色分层、装饰减法 | 层级分从 0.34 提升到 0.84 |
| stage6 | 适应层 | 流体字号、容器查询、稳定性、目标尺寸、性能 | CLS 从 0.31 降至 0.004，可访问性问题降至 0 |

### 六项指标及归属

| 指标 | 含义 | 主要归属层 | stage0 → stage6 |
| --- | --- | --- | --- |
| 行长（measure） | 正文平均行长，舒适区约为 45–75ch | 内容层 | 138 → 64ch |
| 分组比（grouping） | 组间间距与组内间距的比值 | 间距层 | 1.0 → 2.0 |
| 取值种类（consistency） | 页面中可解释的尺度/取值体系 | 尺度层 | 3 → 17 |
| 可访问性问题（a11y） | 焦点顺序逆序与过小目标等问题 | 结构层、适应层 | 6 → 0 |
| 视觉层级分（hierarchy） | 视觉重量排序与业务重要度排序的 Spearman 秩相关 | 视觉层 | 0.05 → 0.84 |
| CLS | 累计布局偏移，越低越稳定 | 适应层 | 0.31 → 0.004 |

这些指标的价值不在于追求绝对心理学精度，而在于把“感觉不对”“层级不清”“页面会跳”等主观问题转成可讨论、可比较、可回归测试的对象。

## 7. 技术架构

### 技术栈

| 技术 | 角色 | 选择原因 / 实现价值 |
| --- | --- | --- |
| Astro 7 | 路由、静态站点生成、页面骨架 | 内容优先；纯静态输出，便于部署与索引 |
| Svelte 5 | 交互孤岛 | 只在需要交互的局部挂载，避免整站 SPA 化 |
| TypeScript 5 | 类型约束 | 约束内容模型、阶段和组件接口，降低配置错误 |
| Zod | 构建期内容校验 | 强制每小节都有理论、讲解、代码和演示 |
| D3 子包 | 信息型可视化与交互实验 | SVG 可访问、数据可重算；按模块导入以控制体积 |
| p5.js | 生成式装饰 | 只做非信息性背景/丝带，不承担数据表达 |
| Shiki | 编译期代码高亮 | 关键代码不依赖运行时高亮开销 |
| Vitest | 单元测试 | 覆盖布局度量、网格、流体公式和色彩相关纯函数 |

### Astro + Svelte Islands

项目明确采用“静态内容 + 局部交互孤岛”而不是单页应用：

- Astro 服务于首屏 HTML、SEO、路由和静态生成。
- Svelte 只承担 Tab、案例时间轴、案例对比、决策树、清单、主题切换、网格覆盖和具体演示等互动。
- 章节的 Tab 控制器只控制 ARIA 状态和面板显隐，正文仍由 Astro 静态输出，避免将长正文重复序列化进客户端组件。
- 演示通过 `demoRegistry` 的动态 `import()` 按需加载；读者不打开演示，就不下载该演示的代码。
- `client:visible` 结合可见性策略，使大量互动内容不阻塞首屏。

### 内容驱动架构

内容不是散落在页面中的 HTML，而是存储为带类型的 TypeScript 模块：

- `src/content/types.ts` 定义 Lesson、Section、Block、CaseStage 等模型。
- `src/content/lessons/ch1-content.ts` 至 `ch6-adaptive.ts` 保存六章内容。
- 所有用户可见字符串使用 `{ zh, en }` 成对存储；中英文在同一处相邻书写。
- `src/content/schema.ts` 使用 Zod 校验：小节 ID 格式、至少一条理论引用、至少 3 个讲解块、非空代码、非空演示、有效案例阶段等。
- `src/content/references.ts` 保存文献；`sectionsCitingReference()` 支持从文献反向找到引用小节。
- `src/content/case.ts` 集中定义案例阶段、指标、改动和指标归属。

这种结构让新增内容更可控，也使“翻译是否齐全”“演示 ID 是否存在”“理论引用是否有效”等问题能够在构建前暴露。

### D3 的使用边界与性能策略

- 信息型图表和教学可视化使用 D3 + SVG，具备 `role="img"`、标题、描述或表格化信息等可访问语义。
- 禁止 `import * as d3 from 'd3'`；D3 子包由 `src/lib/d3-kit.ts` 统一出口。
- 通用子模块形成共享块；重型且少用的模块如 `d3-contour`、`d3-hierarchy` 由对应演示独立动态加载。
- 这样可以避免把整套 D3 或全部演示放进首页包。

### p5 的使用边界

p5 只负责首页的生成式版面、章节页头丝带和部分非信息性装饰。它不用于数据图，因为 canvas 缺少可读的 DOM 结构，不利于屏幕阅读器、测试、复制和检查。

`P5Canvas.svelte` 的关键约束包括：实例模式、动态加载、离开视口或标签页隐藏时停止循环、最大像素密度 2、24fps、`aria-hidden`、不接收指针事件、固定容器高度以避免 CLS。用户设置 `prefers-reduced-motion: reduce` 时，p5 完全不加载，页面使用静态兜底图案。

### 国际化与部署

- 路由级 i18n：`/zh/...` 与 `/en/...` 是两套独立静态页面，不是同页双 DOM 隐藏切换。
- 优点：DOM 不翻倍、语言可被搜索引擎独立索引、切换语言是普通链接、路径可保持在同一章节。
- `astro.config.mjs` 使用 `output: 'static'`，构建结果位于 `dist/`，可部署到任意静态托管服务。
- `SITE_BASE` 和 `SITE_URL` 支持 GitHub Pages 等子目录部署。

## 8. 设计系统与视觉实现

### 统一设计令牌

`src/styles/tokens.css` 是全站数值的单一来源，包含：

- 8pt 间距标尺：4、8、12、16、24、32、48、64、96px。
- 1.25 比例的流体排版音阶：通过 `clamp()` 在 360px 到 1400px 区间插值，且使用 `rem` 保留用户字体缩放能力。
- 行长 `68ch`、24px 基线节奏、12 列网格、24px gutter、1440px 最大宽度。
- 圆角、阴影、动效、层级 z-index、字体栈、六章主题色。
- 明暗主题的颜色、表面层、文字层和层级策略。

亮色主题主要用阴影表达深度；暗色主题中阴影可见性较弱，因此更多依靠不同亮度的表面层表达层级。主题选择保存在 `localStorage`，内联阻塞脚本在首帧就应用主题，以避免闪白。

### 元设计：网站本身就是示例

网站不仅讲布局规则，也在自身实现中遵守这些规则。任意页面：

- 按 `G`：显示 12 列网格覆盖层。
- 在网格已开启时按 `B`：显示 24px 基线覆盖层。
- 按 `Esc`：关闭覆盖层。

该功能是一个“布局审查工具”，让读者可以验证站点是否真的遵循了它所教授的网格与节奏原则。

## 9. 可访问性、渐进增强与性能

### 可访问性

- 提供“跳到主内容”链接。
- 三面板实现 WAI-ARIA Tabs 模式，支持左右方向键循环、Home/End 跳转、焦点管理和正确的 `aria-controls` / `aria-labelledby`。
- 每个小节拥有稳定锚点；Tab 状态可使用如 `#s-1-2--demo` 的深链接分享。
- 无 JavaScript 时，三个面板仍全部可读，体现渐进增强。
- 案例弹窗使用原生 `<dialog>`，复用浏览器提供的焦点管理与 Esc 关闭能力。
- 避免依赖 CSS `order` 改变内容顺序；DOM、阅读顺序和键盘焦点顺序尽量一致。
- 适应层关注 24px 以上目标尺寸、400% 缩放、可重排性和 `prefers-reduced-motion`。
- 全站尽量使用 CSS 逻辑属性，如 `inline-size`、`margin-block`，为 RTL 与不同书写方向留下空间。

### 性能与稳定性

- 静态生成、D3 子包导入、演示动态加载、`client:visible` 共同降低初始负担。
- p5 仅在可见时加载，且 reduced-motion 下不加载。
- 图表和媒体通过 `aspect-ratio`、固定容器或内在尺寸预留空间，减少 CLS。
- 长列表使用 `content-visibility` 等方式降低渲染成本。
- 课程专门讲授并在代码中规避 layout thrashing：布局度量的 DOM 采集会将读操作集中执行，纯计算逻辑与 DOM 操作分离。

## 10. 度量函数与工程化质量保障

### 可测试的布局度量

`src/lib/` 中的函数尽量是纯函数，不直接依赖浏览器 DOM，因此可以被单元测试覆盖。典型能力包括：

- 古腾堡阅读重力权重。
- 视觉重量：面积、对比度、字重、位置的组合。
- 视觉层级分：视觉重量排序和业务重要度排序之间的 Spearman 秩相关。
- 层级倒挂对检测。
- 行长换算与舒适度。
- CLS 会话窗口计算。
- 视觉顺序、键盘焦点顺序逆序对、过小交互目标检测。
- 网格列宽、间距标尺、基线命中率、`clamp()` 参数推导、对比度与感知亮度等。

这使项目能把“布局效果”部分从纯主观评价转为有依据的计算和回归测试。

### 自动化门禁

`npm run verify` 是完整验证入口，依次执行：

1. `parity`：检查中英文内容、文献 ID、演示 ID 和 UI 字典完整性。
2. `tokens`：扫描样式，防止非豁免区域出现随意硬编码的间距或字号。
3. `check`：执行 Astro 和 Svelte 类型检查。
4. `test`：运行 Vitest 单元测试。
5. `build`：构建静态产物。

最近一次已执行的验证结果：

- 中英文一致性检查通过：检查 1214 组双语字符串、20 条文献、32 个演示；有 1 条篇幅比例提示性警告，但无阻断错误。
- 设计令牌检查通过：扫描 29 个样式文件。
- Astro 与 Svelte 检查：0 errors、0 warnings。
- Vitest：3 个测试文件、101 项测试全部通过。
- Astro build：成功生成 21 个静态页面。

## 12. 适合突出强调的项目亮点

后续生成项目介绍时，可优先围绕以下差异点组织，不必只罗列技术名词：

1. **案例驱动而非属性罗列**：一个看板贯穿六章，同一 DOM 和数据只靠 CSS 能力叠加完成演进。
2. **课程编排有依赖逻辑**：六层从内容到适应不是并列目录，而是避免后续用装饰或断点补前面缺口的因果链。
3. **抽象理论可操作验证**：32 个真实计算的交互演示，不使用静态截图代替实验。
4. **主观体验被部分量化**：行长、分组、层级、焦点顺序、目标尺寸、CLS 等被转成可比较指标和纯函数测试。
5. **站点即样例**：设计令牌、12 列网格、8pt 间距、1.25 字号音阶、24px 基线、容器查询等理论直接落实在本站；读者可按键审查。
6. **内容工程化**：双语字符串成对存储、Zod 校验、文献反向索引、演示注册校验、令牌门禁共同保证内容与实现一致。
7. **性能意识贯彻到架构**：Astro 静态生成、Svelte Islands、演示懒加载、D3 子包导入、p5 仅装饰且支持 reduced-motion。
8. **可访问性不是附加项**：语义化 HTML、渐进增强、键盘 Tab 模式、正确 DOM 顺序、缩放/目标尺寸与布局稳定性被纳入教学与实现。
9. **可扩展性明确**：内容、演示、案例指标、决策树和自检清单都有清晰的模块边界和集中注册点。

## 13. 让 GPT 输出内容时应遵守的表述原则

- 将项目表述为“交互式网页布局教学网站”或“案例驱动的前端教学项目”，不要夸大为真实生产数据平台。
- 将 D3 说成“交互式教学可视化/图表”，将 p5 说成“生成式装饰层”；不要说 p5 承担核心数据可视化。
- 说明“指标是教学与评估模型”，不要声称所有 UI 体验都能被绝对客观地量化。
- 对“101 项测试、21 页、32 个演示、20 条文献”等数字，可在需要具体成果时使用；它们来自当前验证状态。
- 强调“纯静态部署、无后端”时，不要虚构用户账户、实时数据、云数据库或 API。
- 若撰写技术亮点，优先解释技术选择解决了什么问题，而不是只堆砌 Astro、Svelte、D3、p5、TypeScript 名称。
